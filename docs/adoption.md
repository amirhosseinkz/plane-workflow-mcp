# Validate adoption with five Plane users

Use this after the quick start and demo are ready. These are preparation materials;
no outreach has been sent and no users or results are claimed.

## A short trial

Ask each participant to install the released wheel, select a project, and get the
read-only briefing without coaching. Record where they pause, the exact failed
step (with secrets removed), whether they reach the first result, and what they
expected. Then ask them to preview one useful task. Writes are optional.

Follow up after a week: did they use it again, for what task, and what stopped them?
Prioritize the most repeated obstacle before expanding features.

Share only in relevant communities that allow it, after reviewing the final demo.

## What to measure

| Stage | Evidence | What a drop-off suggests |
| --- | --- | --- |
| Discovery | GitHub unique visitors and referring sites | Audience/channel or messaging problem |
| Installation | Voluntary tester reports of setup success/failure | Packaging, credentials, or client friction |
| First value | Tester gets a useful briefing or task preview | Onboarding or workflow fit |
| Return use | Tester reports another use within a week | Ongoing usefulness or reliability |

Use counts with denominators (for example, 3 of 5 trial users), not invented
conversion rates. GitHub traffic is maintainer-only; package downloads and stars
are not active-user counts. This plan adds no telemetry. Capture a dated baseline
before promotion and compare equivalent periods after each change.
